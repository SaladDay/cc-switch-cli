## 🚀 빠른 시작

**TUI 모드(권장)**

```bash
cc-switch
```

전체 화면 인터페이스에서 공급자를 전환하고, 계정을 관리하고, 세션을 검토하고, 프록시 상태를 확인할 수 있습니다.

**명령줄 모드**

```bash
cc-switch provider list              # 공급자 목록 표시
cc-switch provider switch <id>       # 공급자 전환
cc-switch use <id>                   # 공급자 전환(단축 명령)
cc-switch provider export <id>       # Claude 공급자를 독립 설정 파일로 내보내기
cc-switch provider stream-check <id> # 공급자 스트림 상태 확인
cc-switch start claude <id>          # 전역 설정을 바꾸지 않고 이 공급자로 Claude 실행
cc-switch start codex <id>           # 전역 설정을 바꾸지 않고 이 공급자로 Codex 실행
cc-switch start codex <id> --shared-sessions # 공급자 간에 영구 Codex 기록 공유
cc-switch start claude <id> --dry-run # Claude를 실행하지 않고 실행 내용 미리 보기
cc-switch auth list                  # 관리 중인 ChatGPT/Codex OAuth 계정 목록 표시
cc-switch sessions list --all        # 저장된 어시스턴트 세션 검토
cc-switch sessions sync-usage --all  # 로컬 세션의 토큰 사용량 및 비용 가져오기
cc-switch config webdav show         # WebDAV 동기화 설정 확인
cc-switch env tools                  # 로컬 CLI 도구 확인
cc-switch mcp sync                   # MCP 서버 동기화
cc-switch proxy show                 # 프록시 경로 및 상태 확인

# 전역 `--app` 플래그로 대상 애플리케이션 지정:
cc-switch --app claude provider list    # Claude 공급자 관리
cc-switch --app codex mcp sync          # Codex MCP 서버 동기화
cc-switch --app gemini prompts list     # Gemini 프롬프트 목록 표시
cc-switch --app hermes provider list    # Hermes 공급자 관리
cc-switch --app openclaw provider list  # OpenClaw 공급자 관리
cc-switch --app pi provider list        # Pi 공급자 관리

# 지원 앱: `claude`(기본값), `codex`, `gemini`, `opencode`, `hermes`, `openclaw`, `pi`
```

여러 터미널에서 서로 다른 공급자를 사용하려면 `cc-switch start`를 사용하세요. 이 명령은 해당 명령으로 실행한 Claude 또는 Codex 세션에만 영향을 줍니다. `provider switch`와 `use`는 기존과 같이 전역 공급자를 변경합니다. TUI에서는 Providers 페이지에서 공급자를 선택하고 `o`를 누르면 같은 방식으로 실행됩니다.

macOS/Linux에서는 `start codex`에 `--shared-sessions`를 추가하면 설정된 Codex 홈의 세션, 보관된 세션, SQLite 기록 인덱스를 공유할 수 있습니다. 각 공급자는 해당 홈의 `.cc-switch-launches/` 아래에 있는 전용 영구 디렉터리를 사용합니다. Codex는 이 디렉터리를 경유하는 세션 경로를 기록하므로 디렉터리를 그대로 유지해야 합니다. 서로 다른 공급자는 동시에 실행할 수 있지만, 같은 공급자의 공유 실행이 이미 진행 중이면 두 번째 공유 실행은 거부됩니다. Codex의 스레드별 쓰기 잠금도 공유되므로, 다른 공급자에서 세션을 재개하기 전에 활성 세션을 닫으세요. 로그인 변경 사항은 해당 공급자에 저장되지만, 실행 시에만 사용하는 설정은 저장된 공급자 설정에 포함되지 않습니다. 기본 `--model`, `resume`, `fork` 인수를 지원하며, 공유 모드에서는 `--config`, `--profile`, `--oss`를 통한 재정의를 지원하지 않습니다.

공유 실행은 전역 기록 설정을 변경하지 않고 기존의 통합 `custom` 공급자 식별자를 사용합니다. 이전 공식 공급자의 세션도 포함하려면 기존 **Unified Codex session history** 설정과 선택적 마이그레이션을 사용하세요. 공급자를 바꿔 대화를 이어갈 수 있는지는 암호화된 추론을 포함한 이전 대화 내용을 연결 대상이 수락하는지에 따라 달라집니다. 기본 임시 실행과 TUI의 `o` 단축키 동작은 변경되지 않습니다.

전체 명령 목록은 "기능" 섹션을 참고하세요.

## 📥 설치

### 방법 1: 빠른 설치(macOS / Linux)

> Windows 사용자는 아래의 수동 설치를 참고하세요.

```bash
curl -fsSL https://github.com/SaladDay/cc-switch-cli/releases/latest/download/install.sh | bash
```

`cc-switch`는 `~/.local/bin`에 설치됩니다. 설치 디렉터리를 바꾸려면 `CC_SWITCH_INSTALL_DIR`을 설정하세요.

- 대상 파일이 이미 존재하면 TTY에서는 확인을 요청합니다. 비대화형 셸에서는 `CC_SWITCH_FORCE=1`을 설정하지 않는 한 덮어쓰지 않습니다.
- Linux의 자동 모드는 정적으로 링크된 musl 빌드를 사용하며, glibc로 대체하지 않습니다. 호환되는 glibc 빌드가 명시적으로 필요한 경우에만 `CC_SWITCH_LINUX_LIBC=glibc`를 설정하세요.

<details>
<summary>수동 설치</summary>

#### macOS

```bash
# Universal Binary 다운로드(권장, Apple Silicon과 Intel 지원)
curl -LO https://github.com/saladday/cc-switch-cli/releases/latest/download/cc-switch-cli-darwin-universal.tar.gz
```

### 🔌 공급자 관리

**Claude Code**, **Codex**, **Gemini**, **OpenCode**, **Hermes**, **OpenClaw**, **Pi**의 API 설정을 관리합니다.

Pi 공급자 관리는 Pi의 기본 추가형 모델을 따르며, `models.json.providers`의 등록 내용을 기준으로 합니다. CC-Switch는 Pi 로그인 자격 증명이나 전역 기본 공급자 및 모델을 변경하지 않습니다.
Pi TUI는 다른 앱과 같은 표, 폼, 단축키 체계를 사용하며, Presets, System Prompts, Prompt Templates를 각각 별도 페이지로 제공합니다.

**주요 기능:** 원클릭 전환, Claude 설정을 독립 파일로 내보내기, 여러 엔드포인트 지원, API 키 관리, 원격 모델 검색, 지원되는 앱에서 속도 테스트와 스트림 상태 확인 등의 진단.

```bash
cc-switch provider list              # 모든 공급자 목록 표시
cc-switch provider current           # 현재 공급자 표시
cc-switch provider switch <id>       # 공급자 전환
cc-switch use <id>                   # 공급자 전환(단축 명령)
cc-switch provider add               # 새 공급자 추가
cc-switch provider edit <id>         # 기존 공급자 편집
cc-switch provider duplicate <id>    # 공급자 복제
cc-switch provider delete <id>       # 공급자 삭제
cc-switch provider export <id>       # Claude가 자동으로 읽는 ./.claude/settings.local.json으로 내보내기
cc-switch provider speedtest <id>    # API 지연 시간 테스트
cc-switch provider stream-check <id> # 스트림 상태 확인
cc-switch provider fetch-models <id> # 원격 모델 목록 가져오기
cc-switch provider export <id> --output ~/.claude/settings-demo.json # 설정 파일 경로 지정
```

### 🌉 프록시 관리 및 모델 중계

지원되는 앱의 프록시 경로를 데몬을 통해 앱별로 확인하고 제어합니다.

**주요 기능:** 앱별 독립 활성화 및 비활성화, 앱별 수신 포트, 데몬이 관리하는 워커, 현재 경로 확인, 대시보드 텔레메트리, 토큰 사용량 집계, 디버깅용 포그라운드 실행 모드.

로컬 프록시는 Claude Code, Codex, Gemini 트래픽을 CC-Switch를 통해 전달할 수 있습니다. OpenAI Responses API 및 Chat Completions 공급자와 연동하고, Codex에서 Anthropic Messages 호환 공급자를 사용할 수 있게 하며, 지원되는 구성에서는 DeepSeek, Kimi, Qwen, OpenRouter, xAI, Groq, Mistral 등 주요 OpenAI 호환 모델에 연결할 수 있습니다.

```bash
cc-switch proxy show                              # 프록시 설정, 경로, 데몬 워커 상태 표시
cc-switch proxy enable                            # Claude 프록시 경로 활성화(기본 앱)
cc-switch --app codex proxy enable                # Codex 프록시 경로 활성화
cc-switch --app gemini proxy disable              # Gemini 프록시 경로 비활성화
cc-switch --app claude proxy config --listen-port 15721
cc-switch --app codex proxy config --listen-port 15722
cc-switch proxy serve --takeover claude           # 포그라운드 디버깅 모드(데몬 관리 경로가 활성화된 동안은 실행 거부)
```

일반적인 CLI/TUI 프록시 활성화 및 비활성화 작업은 데몬을 통해 처리됩니다. 첫 번째 앱의 프록시 경로를 활성화하면 데몬이 자동으로 시작되고, 활성화된 지원 앱(Claude, Codex, Gemini)마다 워커 하나를 실행합니다. 활성 프록시 경로가 더 이상 없으면 자동으로 종료됩니다.

> **플랫폼 지원:** 데몬이 관리하는 프록시는 Unix 도메인 소켓 기반의 감독 프로세스에 의존하며, **macOS와 Linux에서만 사용 가능**합니다. Windows에서는 `proxy enable` / `proxy disable` 및 `daemon` 하위 명령을 사용할 수 없으며, `managed sessions are only supported on unix` 오류가 발생합니다. Windows에서 로컬 프록시를 실행하려면 감독 프로세스 없이 중계를 시작하는 포그라운드 모드를 사용하세요.
>
> ```bash
> cc-switch proxy serve --takeover claude
> ```
>
> `proxy show`와 `proxy config`는 모든 플랫폼에서 사용할 수 있습니다. [#294](https://github.com/SaladDay/cc-switch-cli/issues/294)를 참고하세요.

```bash
# 자체 업데이트
cc-switch update                     # 최신 릴리스로 업데이트
cc-switch update --version vX.Y.Z    # 특정 버전으로 업데이트
```

자동 설치 및 활성화는 현재 `bash`와 `zsh`만 지원합니다. 다른 셸은 `cc-switch completions fish`처럼 자동 완성 스크립트를 직접 생성해 사용할 수 있습니다.

## 🏗️ 아키텍처

### 핵심 설계

- **SQLite 기반 상태 관리**: 핵심 데이터는 기본적으로 `~/.cc-switch/cc-switch.db`에 저장됩니다(`CC_SWITCH_CONFIG_DIR`을 설정한 경우 `$CC_SWITCH_CONFIG_DIR/` 아래에 저장). 기존 `config.json`은 이전 형식의 가져오기 및 마이그레이션을 위해서만 유지됩니다
- **스킬 SSOT**: 스킬 원본 파일은 기본적으로 `~/.cc-switch/skills/`에 저장됩니다(`CC_SWITCH_CONFIG_DIR`을 설정한 경우 `$CC_SWITCH_CONFIG_DIR/skills/`). 설치 상태와 앱별 활성화 상태는 데이터베이스에서 관리합니다
- **안전한 앱 설정 동기화(기본값)**: 아직 초기화되지 않은 앱의 실제 설정 파일에는 쓰지 않습니다(`~/.claude`, `~/.codex`, `~/.gemini`, `~/.config/opencode`, `~/.hermes`, `~/.openclaw`가 예기치 않게 생성되는 것을 방지)
- **원자적 쓰기**: 임시 파일을 만든 뒤 이름을 바꾸는 방식으로 손상을 방지합니다
- **서비스 계층 재사용**: 원래 GUI 버전의 서비스 계층을 100% 재사용합니다
- **동시성 안전성**: 범위 기반 가드를 사용하는 RwLock을 적용합니다

### 설정 파일

**CC-Switch 저장소**(기본값: `~/.cc-switch`, 변경용 환경 변수: `CC_SWITCH_CONFIG_DIR`):

- `~/.cc-switch/cc-switch.db` — 공급자, MCP, 프롬프트, 앱 상태를 저장하는 기본 데이터베이스
- `~/.cc-switch/settings.json` — 설정
- `~/.cc-switch/skills/` — 설치된 스킬 원본(SSOT)
- `~/.cc-switch/backups/` — 자동 순환 보관되는 백업(10개 유지)
- `~/.cc-switch/config.json` — 호환성과 가져오기 작업을 위해 유지되는 기존 JSON

`CC_SWITCH_CONFIG_DIR`을 설정하면 해당 디렉터리가 설정 루트로 사용됩니다. `~/.cc-switch`에 있는 기존 데이터는 자동으로 이동되지 않습니다.

**앱의 실제 설정 파일:**

- Claude: `~/.claude/settings.json`(공급자 및 공통 설정), `~/.claude.json`(MCP), `~/.claude/CLAUDE.md`(프롬프트)
- Codex: `~/.codex/auth.json`(인증 상태), `~/.codex/config.toml`(공급자 및 공통 설정 + MCP), `~/.codex/AGENTS.md`(프롬프트)
  - Codex 설정 디렉터리는 CC-Switch에서 수동으로 지정한 경로를 우선 사용합니다. 별도 지정이 없으면 Codex의 `$CODEX_HOME`이 기존 디렉터리를 가리킬 때 해당 경로를 사용하고, 그렇지 않으면 `$HOME/.codex`를 사용합니다.
- Gemini: `~/.gemini/.env`(공급자 환경 변수), `~/.gemini/settings.json`(설정 + MCP), `~/.gemini/GEMINI.md`(프롬프트)
- OpenCode: `~/.config/opencode/opencode.json`(공급자 + MCP + 런타임 설정), `~/.config/opencode/AGENTS.md`(프롬프트)
- Hermes: `<Hermes home>/config.yaml`(공급자 + MCP + 메모리 설정), `AGENTS.md`(프롬프트), `skills/`, `memories/`. 디렉터리 우선순위는 CC-Switch 설정의 `hermesConfigDir`, 비어 있지 않은 `HERMES_HOME`, 플랫폼 기본값(macOS/Linux에서는 `~/.hermes`, Windows에서는 `%LOCALAPPDATA%\hermes`) 순입니다. Hermes와 동일한 `HERMES_HOME`을 내보내는 환경에서 CC-Switch를 실행하세요.
- OpenClaw: `~/.openclaw/openclaw.json`(공급자 + 환경 변수/도구/에이전트 기본값), `~/.openclaw/AGENTS.md`(프롬프트)
- Pi: `~/.pi/agent/models.json`(추가형 공급자 설정), `~/.pi/agent/settings.json`(읽기 전용 기본값 및 세션 위치), `~/.pi/agent/AGENTS.md`, `SYSTEM.md`, `APPEND_SYSTEM.md`, `prompts/`, `skills/`, `sessions/`

## ❓ 자주 묻는 질문(FAQ)

<details>
<summary><b>공급자를 전환해도 설정이 적용되지 않는 이유는 무엇인가요?</b></summary>

<br>

먼저 대상 CLI가 한 번 이상 초기화되었는지, 즉 설정 디렉터리가 존재하는지 확인하세요. 초기화되지 않은 앱은 CC-Switch가 실제 설정 동기화를 건너뛸 수 있으며, 이 경우 경고가 표시됩니다. 대상 CLI를 한 번 실행하거나(예: `claude --help`, `codex --help`, `gemini --help`, `opencode --help`, `openclaw --help`), Hermes의 경우 `~/.hermes`를 만든 다음 다시 전환하세요.

이 문제는 보통 **환경 변수 충돌**로 인해 발생합니다. 시스템 환경 변수에 API 키(예: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`)가 설정되어 있으면 CC-Switch 설정보다 우선 적용됩니다.

**해결 방법:**

1. 충돌을 확인합니다.

   ```bash
   cc-switch env check --app claude
   ```

2. 관련 환경 변수를 모두 표시합니다.

   ```bash
   cc-switch env list --app claude
   ```

3. 충돌이 발견되면 수동으로 제거합니다.
   - **macOS/Linux**: 셸 설정 파일(`~/.bashrc`, `~/.zshrc` 등)을 편집합니다.

     ```bash
     # 해당 환경 변수가 설정된 줄을 찾아 삭제
     nano ~/.zshrc
     # vim, code 등 원하는 텍스트 편집기를 사용해도 됩니다
     ```

   - **Windows**: 시스템 속성 → 환경 변수를 열고 충돌하는 변수를 삭제합니다.

4. 변경 사항이 적용되도록 터미널을 다시 시작합니다.

</details>

<details>
<summary><b>프록시 시작 시 <code>Address already in use</code> 오류가 발생합니다. 어떻게 해야 하나요?</b></summary>

<br>

다른 프로세스가 이미 프록시 포트를 사용하고 있다는 뜻입니다. 업그레이드나 디버깅 이후, 이전 `cc-switch daemon` / `cc-switch proxy serve` 프로세스가 백그라운드에 남아 있지만 새 프로세스가 여기에 연결되지 못한 경우에 흔히 발생합니다.

먼저 `cc-switch proxy show`로 현재 프록시 포트를 확인하세요. 예를 들어 `configured 15722`로 표시됩니다.

**macOS / Linux:**

```bash
# 포트를 사용 중인 프로세스 확인. 15722는 자신의 프록시 포트로 바꾸세요
lsof -nP -iTCP:15722 -sTCP:LISTEN

# cc-switch 프로세스 목록에서 데몬과 프록시 워커 식별
ps -axo pid,ppid,stat,command | grep '[c]c-switch'

# 데몬에 연결할 수 있으면 먼저 정상적으로 중지
cc-switch daemon stop

# 데몬에 연결할 수 없고 포트가 계속 점유되어 있으면 해당 PID 종료
kill <worker-pid> <daemon-pid>

# 그래도 종료되지 않으면 강제 종료
kill -9 <worker-pid> <daemon-pid>
```

`cc-switch daemon start` 또는 `cc-switch proxy serve`로 명확하게 확인된 프로세스만 종료하세요. 비슷한 번호의 포트를 사용한다는 이유로 관련 없는 앱을 종료하지 마세요.

**Windows:**

```powershell
netstat -ano | findstr :15722
taskkill /PID <pid> /F
```

그런 다음 다시 시작합니다.

```bash
cc-switch proxy show
cc-switch
```

</details>

## 🛠️ 개발

### 요구 사항

- **Rust**: 1.85 이상([rustup](https://rustup.rs/))
- **Cargo**: Rust에 포함

### 명령

```bash
cd src-tauri

cargo run                            # 개발 모드
cargo run -- provider list           # 특정 명령 실행
cargo build --release                # 릴리스 빌드

cargo fmt                            # 코드 포맷 정리
cargo clippy                         # 린트 검사
cargo test                           # 테스트 실행
```

### 라이브러리 전용 빌드

라이브러리로 통합하는 경우 CLI/TUI 의존성을 제외할 수 있습니다.

```toml
cc-switch = { git = "https://github.com/SaladDay/cc-switch-cli.git", default-features = false }
```

`cli` 기능은 기본적으로 활성화되어 있으며, `cc-switch` 바이너리에 필요합니다.

### 코드 구조

```text
src-tauri/src/
├── cli/
│   ├── commands/          # CLI 하위 명령(provider, mcp, prompts, skills, proxy, env 등)
│   ├── tui/               # 대화형 TUI 모드(ratatui)
│   ├── interactive/       # 대화형 진입점 및 TTY 검사
│   └── ui/                # UI 유틸리티(표, 색상)
├── services/              # 비즈니스 로직(provider, mcp, prompt, webdav 등)
├── database/              # SQLite 저장소, 마이그레이션, 백업
├── main.rs                # CLI 진입점
└── ...                    # 앱별 설정, 프록시, 오류 처리
```
